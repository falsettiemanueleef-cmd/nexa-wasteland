## Why the owner must do one editor action

Godot's Android export preset is generated by the Godot editor and contains version-specific export options. It is safer to generate it with the exact Godot 4.7.2 Android editor than to invent a preset file by hand.

## Owner action — generate a debug-only Android preset

On the Android phone:

1. Open **Godot Editor 4.7.2**.
2. Open the existing **NEXA: WASTELAND** project.
3. Open **Project → Export**.
4. Tap **Add… → Android**.
5. Keep the preset for internal/debug testing. Do not configure release keystore credentials.
6. Save the project.
7. Use the Godot file manager or Android file manager to locate the project file named `export_presets.cfg` in the project root.
8. Upload that file to the repository root in GitHub, or send the file here so it can be checked before committing.

Do not upload any keystore, signing key, password, or personal credential. A debug preset is sufficient for the first APK test.

## Export templates

If Godot reports missing export templates, install the matching templates for Godot 4.7.2 from the editor's template manager before attempting export. The templates must match the editor version.

## GABE and Gradle

Godot 4.6+ supports Gradle builds from the Android editor when the Godot Android Build Environment (GABE) app is installed and its Rootfs setup has completed. GABE is not required for the prebuilt APK template export route. For the first private debug APK, prefer the simplest supported export path; do not enable Gradle unless a feature specifically requires it.

## Cloud build decision

A GitHub Actions Android build can be added only after the exact preset and export route are known. A cloud runner also needs compatible Godot 4.7.2 export templates and Android build dependencies. The current headless workflow alone does not produce an APK.

Before enabling cloud builds, verify:
- preset name exactly as generated by Godot;
- whether the preset uses prebuilt templates or Gradle;
- required Android SDK/JDK versions for that route;
- safe handling of signing secrets (not needed for debug);
- APK artifact upload and retention.

## Acceptance criteria

The Android export milestone is complete only when:
1. Godot successfully exports an APK from the real project;
2. the APK file exists and has a non-zero size;
3. the APK installs on the owner's Android device;
4. the game launches and the owner confirms the visible result.

A successful CI headless check is not a substitute for these checks.
